03 · 统一数据格式 rollboard/1

数据源与滚榜引擎完全解耦：适配器负责产出，引擎只消费这份文件。

{
  "schema": "rollboard/1",
  "meta": {
    "id": "2026-final", "title": "2026 校赛决赛",
    "sourceType": "domjudge", "contestId": "3",
    "startTime": "…ISO…", "freezeTime": "…ISO…", "endTime": "…ISO…",
    "durationSec": 18000, "freezeSec": 14400, "penaltyMin": 20,
    "medals": { "gold": 4, "silver": 6, "bronze": 8 }
  },
  "problems": [{ "id": "A", "label": "A", "name": "签到", "color": "#ef4444" }],
  "teams":    [{ "id": "1", "name": "重生之我在ICPC拿金牌", "org": "清水河大学", "starred": false }],

  // 封榜瞬间已公开的状态：attempts = AC 前错误提交数
  "frozen": { "1": { "A": { "attempts": 1, "solved": true, "solveSec": 1240 } } },

  // 仅需「待揭示」的提交：封榜后提交 + 封榜时尚未判定的提交
  "submissions": [
    { "id": "s812", "teamId": "1", "problemId": "F", "timeSec": 15230,
      "verdict": "AC", "penalty": true }
  ]
}
verdict
AC / WA / TLE / MLE / RE / CE / PE / OLE / SE / PENDING
penalty
失败提交是否计入 20 分钟罚时；CE、PE、SE 通常为 false
引擎规则
焦点从最后一名逐行上移：每个揭晓都是「先高亮格子 → 下一步揭晓」；排名变动时该行上移、焦点留在原位交给被挤下来的队伍；空行不跳过（单独一步），下一步才移动焦点；一血 / 获奖单独展示。所有步骤与榜单帧在加载时一次性预计算
交叉校验
DOMjudge 适配器会用 jury 榜单核对重建出的最终通过数与总罚时
